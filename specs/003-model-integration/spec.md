# Feature Specification: Model Integration

**Feature Branch**: `003-model-integration`
**Created**: 2026-01-18
**Status**: Draft
**Input**: Integrated real Kronos model with support for local and Google Colab inference.

## User Scenarios & Testing

### User Story 1 - Local Inference Pipeline (Priority: P1)

Run the full trading loop using the actual `KronosModel` (PyTorch) on the local machine instead of mock predictions.

**Why this priority**: Validates that the core strategy works with the real model, not just theoretical numbers.

**Independent Test**: Can be tested by running `verify_quickstart.py` configured to use `KronosModel` and receiving non-random signals.

**Acceptance Scenarios**:

1. **Given** A local environment with the Kronos repo cloned
   **When** The user initializes `KronosModel` and calls `generate_signals`
   **Then** It loads the model weights from disk (or HuggingFace) and returns predictions.
2. **Given** A dataframe of OHLCV data
   **When** Running the backtest pipeline
   **Then** The predicted values are generated by the PyTorch model, not the mock `x * 1.01` logic.

### User Story 2 - Google Colab Support (Priority: P1)

Ensure the codebase runs seamlessly in Google Colab, handling dependencies, GPU availability, and model loading.

**Why this priority**: Colab is the primary environment for high-compute experiments and model fine-tuning.

**Independent Test**: A specific notebook or script that executes successfully in a Colab environment.

**Acceptance Scenarios**:

1. **Given** A new Colab notebook
   **When** Cloning the repo and installing dependencies
   **Then** `lib/kronos_model.py` successfully imports the model (handling sys.path correctly).
2. **Given** A GPU runtime
   **When** Running inference
   **Then** The model uses `cuda` device automatically.

### User Story 3 - Strategy Integration (Priority: P2)

Update availability to switch between "Mock" strategy and "Real" strategy easily via configuration.

**Why this priority**: Allows for rapid testing (Mock) vs accurate validation (Real) without code changes.

**Independent Test**: Changing a config flag in a script switches the prediction source.

**Acceptance Scenarios**:

1. **Given** A config with `mode: "real"`
   **When** Initializing the system
   **Then** `KronosModel` is instantiated.
2. **Given** A config with `mode: "mock"`
   **When** Initializing the system
   **Then** Random/Mock predictor is used (fast, no GPU needed).

## Requirements

### Functional Requirements

- **FR-001**: The system MUST detect if `Kronos` repository is available and import it dynamically.
- **FR-002**: `KronosModel` wrapper MUST convert model output (logits/next-token) into a usable price/direction prediction column in the DataFrame.
- **FR-003**: The pipeline MUST support running on CPU (if no GPU) without crashing, albeit slower.
- **FR-004**: Colab-specific paths (e.g. `/content/`) MUST be handled or relative paths used effectively.
- **FR-005**: Dependency installation MUST include `torch` (though usually pre-installed in Colab, version compatibility needs checking).

### Key Entities

- **ModelConfig**: Configuration dictionary for model path, device, and batch size.
- **Prediction**: The raw output from `KronosModel`, attached to the DataFrame before Signal Generation.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Local inference runs end-to-end on 100 data points in under 60 seconds (on CPU) or 5 seconds (on GPU).
- **SC-002**: Colab notebook runs successfully from scratch (clone -> install -> backtest) without manual intervention.
- **SC-003**: Integration tests pass for both Mock and Real model configurations.
